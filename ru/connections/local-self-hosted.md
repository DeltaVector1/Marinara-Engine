# Подключение локальной модели или модели на своем сервере

Это руководство объясняет, как подключить приложение Marinara Engine к модели ИИ, которая работает на вашем компьютере или на вашем сервере. Здесь разобраны популярные локальные серверы моделей – Ollama, LM Studio и KoboldCpp – и настройки, при которых они работают.

## Что значит модель на своем сервере

Такая модель ИИ работает на оборудовании, которым распоряжаетесь вы. Сначала устанавливается локальный сервер моделей, затем этот сервер загружает модель и начинает отвечать на запросы по адресу внутри вашей машины. Приложение Marinara Engine обращается к этому адресу, а не к платному облачному сервису.

Чаще всего используют локальные серверы Ollama, LM Studio и KoboldCpp. Каждый из них запускается на вашем компьютере и дает вам собственный эндпоинт. Эндпоинт – это адрес, по которому сервер ждет запросы.

Речь идет о внешних локальных серверах, которые вы устанавливаете и запускаете сами. В приложении Marinara Engine есть и своя небольшая встроенная модель, для которой отдельный сервер не нужен. Про нее рассказывает руководство [Настройка модели Local Model](local-model.md).

Перед началом проверьте, что локальный сервер моделей уже установлен, запущен и модель в него загружена. Marinara не запускает этот сервер за вас, а только подключается к нему.

## Создание подключения Custom

Marinara подключается к локальным серверам через провайдер **Custom (OAI-Compatible)**. Обозначение OAI-compatible значит, что сервер понимает тот же формат запросов, что и OpenAI Chat Completions API. Ollama, LM Studio и KoboldCpp поддерживают этот формат.

Подключение создается так.

1. Откройте панель **Connections** (подключения) в правой части приложения.
2. Нажмите кнопку **New** (создать новое) со значком плюса. Откроется окно **Create Connection** (создание подключения).
3. Введите название в поле **Name** (название), например `Ollama Local`.
4. Выберите провайдер **Custom (OAI-Compatible)** в списке провайдеров.
5. Нажмите кнопку **Create** (создать). Откроется редактор нового подключения.
6. Найдите поле **Base URL** (базовый адрес). Введите адрес локального сервера – адреса перечислены в таблице ниже.
7. Поле **API Key** (ключ API) оставьте пустым. Большинству локальных серверов ключ не нужен.
8. Выберите модель. Нажмите кнопку **Fetch Models from API** (получить список моделей), чтобы загрузить список, который сообщает сервер, и выберите одну из моделей. Другой вариант: ввести идентификатор модели вручную.
9. Нажмите кнопку **Save** (сохранить).

Теперь подключение должно появиться в панели **Connections**. Проверьте его до того, как использовать в чате. Об этом – раздел "Проверка подключения" ниже.

Для локальных серверов поле **API Key** заполнять не обязательно. У провайдера **Custom (OAI-Compatible)** редактор показывает под этим полем напоминание: для локальных моделей вроде Ollama, LM Studio и KoboldCpp ключ можно оставить пустым. Вместо него достаточно задать Base URL.

## Адреса Base URL для распространенных локальных серверов

Поле **Base URL** сообщает приложению Marinara Engine, где ждет запросы локальный сервер. У каждого сервера свой стандартный адрес и порт. Порт – это пронумерованный канал, который сервер занимает на вашей машине. Возьмите адрес того сервера, который вы запустили.

| Локальный сервер | Base URL |
|---|---|
| Ollama | `http://localhost:11434/v1` |
| LM Studio | `http://localhost:1234/v1` |
| KoboldCpp | `http://localhost:5001/v1` |

Слово `localhost` здесь означает "этот же компьютер". Если Marinara работает на том же компьютере, что и сервер модели, эти адреса подходят без изменений.

Поле **Base URL** показывает предупреждение о безопасности: "Only use URLs from providers you trust. A malicious endpoint could intercept your messages and API keys." Вводите только тот адрес, который настроили сами или которому полностью доверяете.

### Про брандмауэр Windows

В Windows локальный сервер бывает заблокирован, даже когда он запущен. У провайдера **Custom (OAI-Compatible)** редактор показывает такое замечание: если прокси или локальный сервер не обнаружен, подключение может блокировать брандмауэр Windows Defender. Чтобы это исправить, откройте **Windows Security** (безопасность Windows), затем **Firewall and network protection**, затем **Allow an app through firewall** и добавьте Node.js или программу своего сервера.

## Переключатель Treat as local/custom endpoint

В редакторе подключения есть раздел **Local / Custom Endpoint** (локальный или свой эндпоинт) с переключателем **Treat as local/custom endpoint** (считать эндпоинт локальным или своим). По умолчанию он выключен. Включите его для своих или проксированных эндпоинтов, особенно если это свой адрес, ведущий к серверу модели в локальной сети.

Пока переключатель выключен, Marinara осторожничает с вызовами инструментов у незнакомых моделей. Если его включить, Marinara всегда будет пытаться вызвать инструмент. Кроме того, ассистент Professor Mari перестает полагаться только на встроенные вызовы инструментов и получает запасной способ – протокол инструментов в формате JSON. Professor Mari – это встроенный ассистент приложения.

Включите этот переключатель, если Professor Mari останавливается после использования инструмента. Включите его и в том случае, если эндпоинт заявляет совместимость с OpenAI, но вызовы инструментов работают ненадежно. Если локальная модель и без него работает нормально, оставьте его выключенным.

## Обращение к серверу на другом компьютере

К вашему собственному компьютеру Marinara разрешает подключаться всегда. Адреса вроде `localhost` и `127.0.0.1` называют адресами обратной петли: они означают "эта же машина". Для подключения они работают сразу, без дополнительной настройки.

Если сервер модели работает на другом компьютере домашней или офисной сети, это адрес частной сети. Такие адреса Marinara по умолчанию блокирует из осторожности. Чтобы их разрешить, тот, кто запускает сервер Marinara, задает переменную окружения. Переменная окружения – это настройка, которую сервер читает при запуске.

Добавьте эту строку в файл `.env` сервера:

```
PROVIDER_LOCAL_URLS_ENABLED=true
```

Сохраните файл и перезапустите сервер Marinara, чтобы изменение вступило в силу. После этого в поле Base URL можно указать другую машину в сети, например `http://192.168.1.50:11434/v1`.

На Android эта настройка включена по умолчанию, пока вы не задали ее сами. Подробнее про файл `.env` и настройки сервера – в руководстве [Настройки сервера: справочник](../CONFIGURATION.md).

## Проверка подключения

Внизу редактора подключения есть карточка **Connection Tests** (проверки подключения). Воспользуйтесь ею, прежде чем полагаться на подключение в чате.

1. Нажмите на подключение в панели **Connections**. Откроется редактор подключения.
2. Нажмите кнопку **Test Connection** (проверить подключение). Так проверяется, доступны ли указанный Base URL и настройки, а еще показывается, сколько времени это заняло.
3. Выберите модель, если она еще не выбрана.
4. Нажмите кнопку **Send Test Message** (отправить тестовое сообщение). Приложение отправит выбранной модели слово "hi" и покажет ответ.

Если обе проверки прошли, локальную модель можно использовать в чате. Откройте чат, откройте его настройки и выберите это подключение.

Та же модель может отвечать на решения, например вопросы активации агентов, без загрузки второй копии в Marinara. Нажмите **Use this model for decisions** (использовать эту модель для решений) в настройках подключения; см. [Модели решений](decision-models.md#on-a-server-you-already-run).

Если проверка не прошла, сначала убедитесь, что локальный сервер все еще запущен и модель загружена. Затем проверьте, что поле **Base URL** точно совпадает с адресом и портом сервера. Для сервера на другом компьютере проверьте, что переменная `PROVIDER_LOCAL_URLS_ENABLED` задана и что сервер Marinara перезапущен.
